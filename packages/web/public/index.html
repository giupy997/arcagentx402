Let your agent pay for what it uses.

ArcRail is the x402 payment agent for Arc, Circle's USDC-native chain. Give any LLM agent one tool and it can buy an API call for a fraction of a cent: price discovered, paid off-chain through Circle Gateway, verified, written to a ledger. No gas, no token, no wallet code in your agent.

One tool call. Four things done.

The agent never touches keys, gas or chain state. It asks for a resource; ArcRail returns the resource and a receipt.

Quote

Fetch the resource. If the server answers 402, read the x402 requirements: price, asset, network, seller.

Check

Spending policy enforced outside the agent: cap per day, cap per seller, rate limit, allowlist. Seller identity resolved on ERC-8004; unknown seller, no payment.

Pay

Sign a USDC authorization against Circle Gateway. Off-chain, gas-free, settled in batches on Arc. Large or deferred jobs go to ERC-8183 escrow instead.

Record

Every attempt lands in the ledger: price, seller, latency, outcome. Exposure per seller is a query, not a guess.

For agents: MCP, or a fetch you already know

Add ArcRail as an MCP server and your agent gets arc_quote, arc_pay, arc_balance and arc_ledger. Or wrap fetch in your own code. The key lives in the rail, never in the model.

  • Works with Claude, ChatGPT, Cursor and any MCP client
  • Policy is the account's, not the prompt's: the model cannot raise its own limit
  • Testnet today; mainnet on 16 September 2026
// claude_desktop_config.json / .mcp.json
{ "mcpServers": { "arcrail": {
    "command": "arc-rail-mcp",
    "env": { "ARCRAIL_NETWORK": "arc",
             "ARCRAIL_KEY_FILE": "/etc/arcrail/agent.key",
             "ARCRAIL_POLICY": "daily=5,per_seller=0.5,per_payment=0.05,identity=required" }
} } }
// tools: arc_quote · arc_pay · arc_balance · arc_deposit · arc_ledger · arc_policy
// or in TypeScript
import { createRail } from "@arc-rail/router";
const rail = createRail({ network: "arc", signer, policy, ledger, identity, agentId });
const { response, receipt } = await rail.fetch("https://api.example/v1/data");
// receipt → { amountUsdc: "0.001", payTo, status: "settled", txHash, latencyMs }
// Hono: a price on a route, settled by Circle Gateway
import { createSeller } from "@arc-rail/seller";
const seller = createSeller({ sellerAddress, network: "arc" })
  .route("GET /v1/forecast", "$0.001");
app.use(seller.middleware());

For sellers: get paid per request, settle in USDC

Put a price on a route. Buyers pay through Circle Gateway; you receive USDC on Arc in batched settlements, no invoicing, no chargebacks, no API keys to leak. ArcRail lists your endpoint to every agent on the rail.

  • x402 standard, so any x402 buyer can pay you, not only ArcRail agents
  • Settlement guarantee and seller bonds arrive in phase 2
  • Your prices, latencies and failure rates become your reputation

Why this only works on Arc

Per-call pricing needs a fee you can predict. Arc's base fee is an exponential moving average of block usage with a 20 gwei floor, and the next block's fee is published in the current header. Gas is USDC, so an agent's cost and its revenue are in the same unit. Finality is deterministic in under a second, so "paid" means paid.

Gas is USDC

No native token to acquire and no volatile denominator between what an agent earns and what it spends.

Standards on day one
